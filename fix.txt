B. JWT: refresh tokens + logout + blocklist + revoke on password change
═══════════════════════════════════════════════════════════════

Current problems:
- Only access_token, expires 8 hours
- No create_refresh_token, no JWT_REFRESH_TOKEN_EXPIRES
- No /api/auth/refresh
- No /api/auth/logout
- No token_in_blocklist_loader
- Password change does not invalidate existing JWTs

Implement:

1. Config in create_app:
   JWT_ACCESS_TOKEN_EXPIRES  = timedelta(minutes=15)   # short-lived
   JWT_REFRESH_TOKEN_EXPIRES = timedelta(days=7)

2. Import create_refresh_token from flask_jwt_extended.

3. Login (and any place that issues tokens):
   Return:
   {
     "access_token": ...,
     "refresh_token": ...,
     "user": ...
   }
   Keep additional_claims: role, outlet_id, user_id, admin_department, is_superadmin.
   Optionally add token_version from user if you implement version bump (see 7).

4. POST /api/auth/refresh
   - @jwt_required(refresh=True)
   - Reject if token is blocklisted
   - Issue new access_token (and optionally rotate refresh_token)
   - Rate-limit reasonably (e.g. 30/minute)

5. Redis JWT blocklist:
   - Key: revoked:{jti}  value: "1"  TTL: remaining seconds until exp
   - Register:
     @jwt.token_in_blocklist_loader
     def check_if_token_revoked(jwt_header, jwt_payload):
         ...

6. POST /api/auth/logout
   - @jwt_required()  (access token)
   - Put current access jti in blocklist with TTL until exp
   - If client sends refresh_token in body, also revoke that jti
   - Return 200 {"message": "Logged out"}

7. Revoke on password change:
   Paths: /api/auth/change-password, profile password update, admin reset of user password if any.
   Prefer token_version on User model:
   - Add column token_version Integer default 0 (migration or create_all-safe)
   - Put token_version in JWT claims at login
   - On password change: user.token_version += 1; commit
   - In blocklist loader OR a @jwt.additional_claims / token check: reject if claim token_version != user.token_version
   Also revoke current jti(s) in Redis when password changes.
   Same idea on ban/deactivate if easy.

8. Do not break existing role_required / department_required / jwt_required routes.
